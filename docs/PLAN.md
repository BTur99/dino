# План доведения агента до 15 000+ очков

Дата: 2026-11-19
Игра: wayou/t-rex-runner (локально на `http://127.0.0.1:8000/`)

## Цель

Стабильно **≥ 15 000 игровых очков** (медиана последних 20 eval-эпизодов ≥ 15 000
и один чистый воспроизводимый прогон ≥ 15 000).

## Метрика счёта (важно)

Счёт в игре = `Runner.distanceRan` (на экран выводится `Math.ceil(distanceRan)`).
Текущий код пишет в `max_score` число **шагов цикла**, а не игровой счёт — это не то же самое.

Формула набора очков:
- `distanceRan += currentSpeed * deltaTime / msPerFrame`, `msPerFrame = 1000/60`
- скорость: `SPEED = 6` → `MAX_SPEED = 13`, рост `ACCELERATION = 0.001`/кадр (≈ +0.06/с)
- интеграл: `distance(t) = 360·t + 1.8·t²`

Отсюда **15 000 очков ≈ 35–40 секунд чистой игры** (скорость при этом ~8 из 13).
Цель — не марафон, а ~40 секунд без смертей при высокой плотности кактусов и птиц.

## Текущая архитектура

- Состояние снимается из `window.Runner.instance_` через JS (`page.evaluate`), без скриншотов.
- Признаки: дистанция, высота препятствия, признак птицы, ширина, второе препятствие
  (сейчас огрублены в дискретные корзины — в M1 перейдём на непрерывные).
- Действия: NOOP / JUMP / DUCK. Клавиши через `page.keyboard`.
- DQN: обычный (не Double), MLP 5→64→64→3, replay `deque(250k)`, MSE loss, Adam.
- 20 воркеров Playwright (persistent context), общий `policy_net`/`target_net`/`memory`.

## Критические блокеры (из ревью)

1. Награда за прыжок: `jumping` берётся ПОСЛЕ действия → каждый кадр в воздухе `-0.5`,
   успешный прыжок в сумме `-15…-20`. Оптимальная политика — не прыгать.
2. «Присесть → прыгнуть» не работает: перед Space не отпускается `ArrowDown`.
3. Птицы не детектируются: `obstacle.type` не существует, правильное поле
   `obstacle.typeConfig.type === "PTERODACTYL"` → `isBird` всегда `false`.
4. Нет `isfinite`-проверок и `clip_grad_norm_` → один NaN убивает веса навсегда.
5. Чекпоинт = только веса политики: нет optimizer/replay/шага/stats → `--resume` деградирует.
6. Target-сеть обновляется раз в 1000 **эпизодов** (не шагов); нет Double DQN.
7. Сиды неполные (`torch.manual_seed` нет, JS `Math.random` не сеется).
8. Закрытие окна не останавливает воркер (`lambda` без аргумента); NOT_PLAYING/ERROR
   пишет мусор в буфер и может упасть с `NameError`.

## План по этапам

| Этап | Содержание | Кто | Критерий |
|---|---|---|---|
| M0 | Харнесс реального счёта (`distanceRan`), длина эпизода, FPS, baseline случайного агента | ml-engineer | счёт пишется, baseline ~200–600 |
| M1 | Среда v2: непрерывные признаки, корректный terminal, счёт как награда, фикс reward/jump/duck/птиц | ml-engineer | эвристика набирает 300–500 |
| M2 | Ядро RL: Double DQN, PER, Huber, clip grad, target по шагам, полный чекпоинт, resume | ml-engineer | переживает кактусы → 1 000+ |
| M3 | Птицы и скорость: duck/jump по высоте, curriculum, тюнинг | ml-engineer + reviewer | 5 000+ |
| M4 | Масштаб: `HEADLESS=True`, больше воркеров, длинный прогон, отбор чекпоинта | ml-engineer + diagnose | медиана ≥ 15 000 |

После каждого этапа `reviewer` прогоняет diff, `github` коммитит в ветку `feat/…` с PR.

## Первый спринт (фикс критики + M0/M1/M2 ядро)

1. Зафиксировать `current_jumping` до действия, убрать `-0.5` в константу конфига;
   проверить, что успешный прыжок даёт положительную сумму reward.
2. В ветке JUMP отпускать `ArrowDown` перед `Space`; проверить «присел → прыгнул».
3. `isBird` через `typeConfig.type === "PTERODACTYL"`.
4. `NOT_PLAYING/ERROR` → конец эпизода без записи перехода; `next_state = state` в начале;
   `lambda _: stop_event.set()`.
5. Чекпоинт: `optimizer`, `step`, `stats`, `target`; атомарная запись (`tmp + os.replace`);
   снимок весов до `to_thread`; `load_all` в try/except.
6. Double DQN + Huber + `clip_grad_norm_`; `optimize_model` по расписанию (не каждый шаг),
   `torch.set_num_threads(2)`; target по шагам (или Polyak τ≈0.005).
7. `isfinite` на признаках/reward, логировать loss раз в N шагов.
8. `torch.manual_seed` до создания сетей, пересеять JS, `HEADLESS=True` по умолчанию.
9. `GAME_URL = "http://127.0.0.1:8000/"`; харнесс реального счёта `distanceRan`.
10. Smoke 2–3 минуты: `avg_last_100` растёт, loss не NaN, счёт реально идёт.

## Риски и меры

- Скорость растёт с очками → признаки по TTC (`distance/speed`), не по пикселям.
- Птицы рандомны → судим по медиане 20 eval, не по 1 эпизоду.
- 20 воркеров на 12 потоках + реальное время → `HEADLESS=True`, при нужде снизить воркеры.
- `.venv` 5,8 ГБ CUDA-колёс впустую (GPU нет) → позже CPU-сборка torch, для фичевого DQN GPU не нужен.
- Хрупкость Playwright (blur → пауза, закрытие окна) → `diagnose` ловит зомби-контексты.
